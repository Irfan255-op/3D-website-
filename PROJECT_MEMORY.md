# Project Memory — shaikh.labs

Read this before touching `resources/js/app.js` or `resources/views/home.blade.php`. The hero sphere system especially carries a lot of decisions that aren't obvious from the code alone — this file exists so a new session (or a future me) doesn't have to re-derive them or repeat a dead end already walked into once.

**Update this file after every change that affects the hero sphere, homepage structure, or brand system** — not every tiny CSS tweak, but anything a future session would otherwise have to re-discover by reading a diff or asking the user again. Keep the changelog append-only (newest entry on top), and keep the "Current state" section in sync with reality, not with what was *intended* — if something was tried and reverted, say so and say why, don't just delete the trace.

## Design direction (read first)

The site is **fully monochrome**: paper (`--paper` #f6f6f7) for the homepage hero, ink (`--ink-900` #08080a) for everything after it and for every other page. The orb is **chrome/silver** (`uColorA/B/C` #bfc0c6 / #e9e9ed / #d2d3d9) — it was pearl-pink for one round, the user asked for greyscale, and every 3D material followed: halo rings, shards, gyroscope, blocks, shell, swarm. Iridescence on the physical materials is down to a trace (0.22–0.3) so chrome glints at grazing angles without rainbowing; the orb's nacre is a whisper (0.06). The **logo keeps its blue gradient** — the one spot of colour on the site. The `--color-brand-*` ramp holds **greys**, which turns every pill, toggle, rule, focus ring and marker monochrome from one place.

**There are no cards.** Content sits directly on the page under a single hairline rule. Section headings run to ~9rem against 11px labels; that ratio is the whole editorial effect. The 3D is **large but contained** (scale 1.5–1.7, |x| ≈ 2.1): it fills roughly a third of the width and only kisses the edge. A first pass at 2.2–2.5 cropped it off every side and the user said it was "taking too much space" — on a 1920px screen it dominated worse than my 1440px tests showed. Dependent scales (`DEVICE_SCALE` 0.85, compact ×0.5, `FLOOR_OFFSET`) all track the group scale; change one and check the others. Chrome recedes while you read.

This replaced a saturated-blue world of translucent glass cards, 36–48px headings and a politely-boxed orb, after the user pointed at cyphercapital.com and edolus.com. The lesson from both: they feel expensive because of what they *removed*. Do not reintroduce panels, tints or mid-sized type without a reason.

## Stack

- Laravel 13 + Tailwind CSS v4 + Vite, local dev via XAMPP/MySQL (`DB_DATABASE=corefolio`)
- Brand: **shaikh.labs**, blue gradient (`#1557e8` → `#168bff` → `#27c9f2`, tokens `--color-brand-*` / `--color-brand-cyan` in `resources/css/app.css`)
- GSAP + Lenis for scroll/motion; three.js (dynamically imported, code-split) for the homepage hero sphere only
- `motion` (vanilla, non-React — NOT Framer Motion/React) — added for exactly one effect, see changelog. Dynamically imported (own ~53KB chunk), not in the main bundle. Don't reach for this by default; GSAP already covers everything else on the site, and this one spot uses it specifically for its spring-physics shorthand, not as a general replacement.

## Current state — homepage (`resources/views/home.blade.php`)

Sidebar shell (`resources/views/layouts/app.blade.php`): fixed left **icon rail**, `5rem`/80px wide on desktop (`lg:w-20` / `lg:pl-20` — was a 256px text-link sidebar, `16rem`/`lg:w-64`, narrowed per user request), mobile falls back to a top navbar below `lg` (unchanged, still full text labels in a hamburger menu).

Six sections, each a translucent `.stage-card` on one side of the viewport with the WebGL sphere on the other (card side alternates via `data-side="right"`):

| # | Section | Card side | Central object | Card component |
|---|---|---|---|---|
| 1 | Hero `#top` | left (text) | smooth pearl-pink orb (hover-reactive) | staged intro, status dot, scroll cue |
| 2 | About `#about` | right | orb, **soft rolling waves** (`data-sphere-spike="1"`) + Motion spring bloom; once settled the swarm forms a **particle portrait** (optional, needs a photo) | bio |
| 3 | Services `#services` | left | orb + a **Möbius chrome ribbon** looping it (`data-sphere-bands="1"`), data packets riding its spine | **exclusive `<details>` accordion** |
| 4 | Skills `#skills` | right | a **trefoil knot** cut into one chrome segment per skill, not the orb (`data-sphere-gem="1"`); hover a skill → that segment lights and swells | skill tags |
| 5 | Work `#work` | left | a **shattered chrome mirror**, not the orb (`data-sphere-discs="1"`): ~120 triangular shards drifting and tumbling at rest; hover a row → they fly back together into the whole mirror, which lights with that site's real screenshot; leave → it shatters again | interactive project rows |
| 6 | Contact `#start` | right | orb, **breathing beacon** glow (`data-sphere-beacon="1"`), with **chrome droplets** streaming in and merging into it, each landing rippling the surface | **"How we'll work" scroll-drawn timeline** |

All four section shapes share one `chromeMaterial()` recipe (metalness 0.94, roughness 0.12, clearcoat, trace iridescence) — liquid metal lit by the `RoomEnvironment`. The attribute names `gem`/`discs`/`bands` are historical (fourth design each) and not worth the churn of renaming; `SHAPE.gyro`/`SHAPE.blocks` in the swarm likewise now mean knot/slabs.
| 7 | Finale `#finale` | — (centred, no card) | **3D shaikh.labs logo** (`data-sphere-logo="1"`), formed by the swarm | colophon line only |

(The `gem`/`discs` attribute names are historical — they've driven three successive designs each; the names were never worth the churn of renaming.)

The sphere's per-section target (position, scale, rotation, spike, bands, fade, gem, discs, beacon) comes from `data-sphere-*` attributes read in `measureWaypoints()` in `app.js`, re-measured live from the DOM (not baked into fixed scroll percentages) so it stays correct across resizes and content changes. A dwell/ease curve (`segmentEase`, `DWELL = 0.28`) holds the sphere at each waypoint's pose while that section is being read, rather than drifting the whole time.

**Sphere material (current)**: pearl-pink (`uColorA/B/C` `#e8a0bc/#f5c2d6/#f29bc4`), near-opaque (`glassAlpha` 0.9–0.99 — the blue canvas would otherwise bleed through), wrapped half-Lambert diffuse with lavender-tinted shadows (`ambient 0.78`, `shadowTint`), a milky face-on frost (0.3), a rim-masked **nacre** thin-film hue drift (cosine palette on fresnel + `n.y` + `vWave`), and a cool cyan **bounce light** from below-left so it sits *in* the blue world. History below: it started as blue frosted glass.

**Sphere material (original notes)**: frosted glass (fresnel-driven alpha — transparent facing the camera, solid at the rim), not solid gloss. Built with a custom `ShaderMaterial`, not `MeshPhysicalMaterial` — no real refraction (nothing bends behind it), just alpha blending against the actual CSS background behind the canvas, which is enough to read as glass. True refraction would need a render-to-texture pass; flagged as a possible future upgrade, not started.

**Lighting for the physical-material shapes (current)**: `scene.environment` is a PMREM-prefiltered `RoomEnvironment` (`three/addons/environments/RoomEnvironment.js`, imported in parallel with three in `initHeroSphere()`, ~2KB chunk), `environmentIntensity 0.85`, plus the `keyLight` (2.2) and a weak ambient (0.25). Gyroscope rings (`#f6d9e6`), blocks (`#ece6f7`) and burst shards are pearl `MeshPhysicalMaterial` with `iridescence` — they were brand blue and read as navy silhouettes on the blue canvas. No tone mapping on the renderer, deliberately: it would shift the approved colours of the `MeshBasicMaterial` halo rings.

**Skills (gem) and Work (discs) are genuinely different objects, not sphere variants** *(paragraph describes the first designs — see the table above and the changelog for what's current)* — a flat-shaded `IcosahedronGeometry(1.05, 0).toNonIndexed()` and a stack of four `CylinderGeometry` discs respectively, both `MeshPhysicalMaterial` (clearcoat, no transmission — kept simple and reliable rather than chasing real refraction here too). They're lit by **real scene lights** (`keyLight` a `DirectionalLight`, plus one `AmbientLight`) added once near the top of `buildHeroSphere` — the only things in the scene that respond to real lights; the orb, rings, and bands all fake their own lighting inside their own shaders/materials and ignore `keyLight` entirely. `uGlobalAlpha` on the orb's shader cross-fades it out whenever `gem` or `discs` is active (`shapeSwap = min(1, gem + discs)`), so only one central object is ever visible at a time. The orbit rings and their markers are deliberately **not** part of that fade — they stay constant across every section regardless of which central object is showing, which is what makes the shape swap read as "the same stage, different exhibit" instead of a different scene entirely. Contact's beacon is the cheapest of the three: no new geometry, just a `uBeacon` uniform that adds a slow `sin(uTime)` pulse of soft light to the existing orb shader, strongest facing the camera rather than at the rim (so it doesn't compete with the glass fresnel sheen).

**Other sphere decorations, each independently driven by scroll state:**
- Two orbit rings with a moving marker + comet trail on each (`rings`, `ringDots`)
- Tech-stack text bands (`bandSide`, `bandTop`) — canvas-texture-based scrolling text, front/back faces handled separately so the back never shows mirrored lettering
- Ferrofluid spikes — vertex-shader lattice displacement (`spikeField`), independent of the (now-removed) tendril system below

**Background layers** (`.stage-wash`, `.stage-ambient`, `.stage-blob`, `.stage-grain`, all `position: fixed`, stacked by DOM order): a slow scroll-tied gradient wash (driven by `--scroll-progress` CSS var, set every frame in `tick()`), two drifting blurred blobs, and a JS-generated dithered noise texture (real per-pixel randomness, not SVG `feTurbulence` — the SVG version is still the CSS fallback if JS fails). The noise is intentionally light-biased (150–255 range) because it sits under `mix-blend-mode: multiply` — full-range noise there reads as harsh static, not film grain. Learned this the hard way; don't widen that range without re-checking against a screenshot.

**Other homepage mechanics:**
- `[data-scramble]` on section `h2`s — characters scramble through random glyphs then resolve left-to-right on scroll-into-view (`IntersectionObserver`, not GSAP). NOT applied to the hero `h1` — it has nested markup for the chromatic-lens hover effect that a `textContent` swap would break.
- `[data-magnetic]` on the five visible CTA buttons — pulls toward the cursor via `gsap.quickTo`. The navbar's own "Let's talk" link also has the attribute but is genuinely invisible at desktop widths (`lg:hidden` on its parent `<header>`, which is mobile-only since the sidebar took over) — don't be fooled by it into thinking magnetic buttons are broken; test against a visible one.
- Canvas fades in via `intro.opacity` (starts at 0, both in JS and as the CSS default on `.stage-canvas`) — masks the gap between page paint and the first WebGL frame actually landing.
- Motion-pause button stops the *ambient* animation (idle breathing, orbit spin) but scroll-driven response keeps working — intentional, not a bug.
- **Load choreography**: `initPageLoader()` sets a module-level `pageReady` promise (resolves when the loader starts fading, capped at 3s to match the CSS auto-hide). The hero copy (`[data-sphere-hero] [data-animate]`) starts hidden and rises in a stagger on it; the orb's `intro` tween waits on it too.
- **Scroll choreography** (`initScrollReveal()`): homepage `.stage-card`s enter from the side they sit on (`x ±90`, `rotationY ±9`, `expo.out`; plain rise below 1024px), then their children stagger in — `[data-stagger]` containers stagger per child. `[data-hero-content]` drifts up/dims (scrubbed) as you leave the hero.
- **`is-dark` class on `<html>`** (renamed from `is-blue`): toggled by the curtain on the homepage (`growP >= 1`), and set **server-side in the layout on every non-home route** — the hero is the one light moment on the site, so the other pages start in the dark world already. Everything dark-world keys off it.
  **Surfaces carrying their own white fill must be inverted explicitly** — the blanket `is-dark .text-slate-900 → paper` rule otherwise leaves white type on a white card. Caught on the Work index (`.project-card`) and the contact form (inputs, validation states); both have explicit overrides now. Check this on any new white-backed component.
- **Receding chrome** (`initChromeFade()`): adds `chrome-dim` to `<html>` 1.8s after scrolling stops, fading the chapter rail, caption, motion toggle and the rail's nav icons. Opacity only — nothing leaves the accessibility tree, and `focusin`/hover bring it straight back.
- **Loader is an entry ritual**: a counter eases to 90, holds, then runs to 100 once the page is genuinely ready, over a filling hairline. The *pace* is designed (real load progress arrives in a few large lurches and reads as broken); the *finish* is honest. Still capped at 3s by the CSS auto-hide — a portfolio visitor wants the work, not a patience test.
- **Chapter rail** has a progress hairline (`.chapter-rail__track::after`, `scaleY(var(--scroll-progress))`) and a bead beside the current chapter. The bottom caption doubles as the **scroll cue** in the hero (`.is-cue`, hero waypoint caption is "Scroll to explore").
- **Light-dust field** (`dust`, `THREE.Points`, 720 desktop / 260 compact): all motion in the vertex shader (scroll parallax by depth, idle drift, pointer offset); `uAlpha = dustPresence` = the curtain's `reappearP`, so it only exists on the blue canvas.
- **Orb hover**: per-frame ray-vs-bounding-sphere test (cached `canvasRect`, desktop only, only while `uGlobalAlpha > 0.6`) → `orbHover` adds distortion + spin; toggles `#cursor-ring.is-orb`.
- **Sidebar scroll-spy** (`initSectionSpy()`, IntersectionObserver, works under reduced motion): `[data-spy]` links + one sliding `[data-sidebar-indicator]` bar; falls back to the `aria-current="page"` route link on Work/Blog.
- **Footer**: velocity-reactive marquee (`initMarquees()`, Lenis velocity → boost + direction, wraps at -50%, only ticks on screen), live IST clock (`initLocalTime()`, server-rendered first), back-to-top (`initBackToTop()`).
- **Cards**: cursor spotlight (`initCardSpotlight()` feeds `--spot-x/y`; `--spot-o` is an `@property` so it can transition).
- **Scene graph**: `sphere` (pose/arc/roll) → `spinner` (drag spin; holds orb, bands, gyroscope, blocks, logo, swarm) — the halo rings/markers and burst shards stay directly under `sphere`.
- **Swarm morph** (`swarm`, `THREE.Points`, 14k desktop / 5k compact): every section-to-section transition. Pose key `morph` = waypoint index (generic lerp), so `floor` = segment and fraction `m` = progress; `presence = smoothstep(m,0,.14)·(1−smoothstep(m,.86,1))`; every solid shape is multiplied by `solid = (1−presence)(1−burst)`. Per-particle homes on each shape (`position`=orb, `aGyro`, `aBlocks`, `aLogo`), all `flowOrder`-sorted so morphs flow coherently. Waypoints carry `shape` (`SHAPE.orb/gyro/blocks/logo`). Start→finale is special-cased in the shader: thirds of the swarm stream in as the gyroscope (upper left) and blocks (lower right).
- **Flight paths** (`FLIGHT_PATHS`, indexed by segment): every transition takes its own route through the scene — vault over the top, swing low past the camera, fall far back, spiral out — instead of the same left-right slide six times. Each entry is the x/y/z detour at the peak plus the attitude (roll/pitch/yaw) it flies in; `bump = sin(π·m)^1.15` peaks mid-transition and resolves to 0 at both ends, so the detour always dissolves cleanly onto the resting pose. Scaled by `vigour` (scroll velocity), so a hard scroll throws it further. Compact view keeps the depth and height but zeroes the sideways swing.
- **No film grain.** There was a `.stage-grain` layer (JS-generated dithered noise under `mix-blend-mode: multiply`); removed at the user's request — element, CSS, keyframes and the `initGrainTexture()` generator all gone. `.stage-vignette` stays and now carries the lens falloff alone.
- **`crossing`** (the bank/tumble/stretch) is now `sin(π·m) × travel` (travel = |Δx|/3.2 of the segment) — NOT `1 − |x|/1.6`, which mistook anything resting near centre (mobile, the finale) for mid-crossing.
- **Touch** (`orbHover`, `uTouch`/`uTouchDir` dent, `triggerRipple()` → `uRipples[8]`/`uRippleAmp` ring buffer, waves in `rippleField()`), **drag** (`pointerdown` only when `orbHovered`; `applySpin()` premultiplies `spinner.quaternion`; release momentum decays and slerps home), **fling** (release > `FLING_SPEED` 18 rad/s → `burstStart`, `burstAmountAt()` drives the shards). No `preventDefault()` on pointerdown — it suppresses mousemove and froze the custom cursor.
- **Work devices** (`DEVICE_LAYOUTS` phone/laptop/monitor/tablet, `updateBlocks()`): blocks spring-follow either grid poses or device tiles; `levelQuaternion` cancels the group's section roll; screen texture drawn per project from the row's DOM; screen floats `SCREEN_STANDOFF` off the tiles (closer and seams poke through — see changelog).
- **Services packets** (`packetSystems`, CPU-simulated, children of each band): each landing calls `triggerRipple()`.
- **Depth rule, now everywhere**: physical materials write depth only when ~opaque (`depthWrite = opacity > 0.9x`), never while fading; invisible solids are `.visible = false`, not just alpha 0 — otherwise they punch holes in the swarm.
- **One shared breath** (`BREATH_SECONDS = 3.6`, `BREATH_RATE`): the orb's swell, the gem core (double-time), Contact's beacon and the oyster's idle all use it; `tick()` writes `--breath` (0..1) to `<html>` and adds `.has-breath`, which switches the CSS pulses (status dot, finale colophon) from their own keyframes to the live value so they're in *phase*, not merely the same tempo. `--breath-duration` in app.css mirrors the constant — keep in sync.
- **Refraction** (`pageBackground()` in the orb's fragment shader): the page background is CSS under a transparent canvas, so it can never be sampled as a texture. The shader instead *rebuilds* the known gradient (`uBgOrigin` = the curtain's own origin, `uBgBlue` = its `growP`) and refracts that, with R/G/B bent by different amounts for dispersion. Painted into the body (`clarity`), not left to alpha blending, because the orb is deliberately near-opaque. **Keep `clarity` low (0.18)** — a first pass at 0.42 turned the pearl lavender over the blue sections.
- **Ground contact** (`groundMesh`, `FLOOR_Y = -1.5`): an implied floor, not a real one — a plane laid flat would be edge-on to the camera and invisible. A soft ellipse that spreads/fades as the orb lifts through a crossing and tightens as it settles, plus a light ring that fires on arrival (`landingRing`, driven by `settling` watching `presence` fall).
- **Oyster** (`buildShellGeometry()`): parametric scalloped dome, no model file. One geometry drawn twice — `FrontSide` chalky outer, `BackSide` nacre inner. Lid is hinged at the back rim (`shellHinge`), not its own origin, or it would swing through the lower shell. Sized to *frame* the orb (`SHELL_RADIUS` 1.32 vs orb 0.95); 1.46 with deep bowls swallowed it.
- **Particle portrait** (`SHAPE.portrait`, `buildPortrait()`): optional. Laravel resolves `public/images/portrait.(jpg|png|webp)` in the layout and passes `data-portrait` on the canvas — probing from JS fired 404s into every visitor's console. Depth from luminance (bas-relief), brightness carried per particle in `aPortraitLuma` so a dark background falls away on its own. Plays once, on a timer (`portraitState()`), gated on `scrollCurrent.spike` as a self-maintaining "is About the active section" proxy, and faded by `aboutFocus` if you leave mid-play.
- **Adaptive quality** (`QUALITY_TIERS`, `watchQuality()`): the scene measures its own frame time and steps down — pixel ratio first, then swarm/dust draw counts, then the orb's segment count. **Downgrades only** (upgrading would visibly pulse). Two things make it work, both found by testing rather than reasoning: it counts **seconds of wall time, not frames** (a frame count reacts slowest on the devices that need it most — the frame-counted version never fired at all under 20× throttling), and it is fed the **uncapped** frame delta (everything else clamps to 0.1s, which would make a struggling device look merely mediocre). Compact view starts one tier down. The swarm is thinned with `setDrawRange`, which only draws a contiguous prefix — hence `SWARM_SHUFFLE`, one shared permutation applied after every shape's flow sort (including the portrait's) so any prefix is a representative scatter *and* particle correspondence across shapes survives.
- **Browser support** (verified in Chromium, WebKit and Firefox, zero errors in each): `:has()`, `@property`, `::details-content`, `color-mix`, `backdrop-filter` and WebGL are everywhere. **`interpolate-size` is Chrome-only** — the Services accordion simply snaps open elsewhere instead of animating, which is the intended degradation. `.stage-card` declares `--spot-o: 0` as a plain property *as well as* the `@property` initial-value: without it, a browser lacking `@property` would make the spotlight `calc()` invalid at computed-value time and drop the **entire** background declaration, leaving a transparent card with unreadable text on the blue.
- **Layout rhythm**: the six sections no longer share one shape. Services is `.stage-card--bare` (no card, white text straight on the blue, oversized display type) and Skills is `.stage-card--split` (two columns). **The bare panel has a full reduced-motion restore in app.css** — with no canvas there is no blue, and white-on-white would be invisible.
- **Section numerals** (`.section-numeral`): huge ghosted folio numbers. Placed *opposite* the card via `:has()`, because behind an opaque card they're simply not visible; the bare panel is excepted, where it shows through from behind the title.
- **Vignette + grain** (`.stage-vignette`, `.is-blue .stage-grain`): both only over the blue. The mood gradients in `.stage-ambient` went from one 16% layer to two at 42%/30%, which is what finally makes the per-section palettes read as different colours rather than one blue.
- **Mobile parity**: `adapt()` lifts the shape to `y + 1.5` at 0.72 scale and the canvas renders at 0.88 (was centred behind the copy at 0.4); `.stage-section` gets `padding-top: 46vh` under 1024px so the shape has that space. Touch gets drag/fling/tap (`pointerHitsOrb()` tests on contact, with a more forgiving radius) and device tilt (`requestTilt()`, gesture-gated on iOS).
- **Real project art**: screenshots of the four live sites in `storage/app/public/projects/`, with `projects.image` pointing at them. Used by the Work cards, the case studies, and the 3D device screens (`screenshotFor()` — lazy on hover, and a photo arriving after the screen is already lit resets `screenProject` to force the rebuild). Re-capture with `scratchpad/capture-sites.js`.
- **Orb hint** (`initOrbHint()`): one-time, localStorage-gated (wrapped in try/catch — it throws in some privacy modes), positioned beside the orb each frame, removed on any interaction.
- **Keyboard nav** (`initKeyboardNav()`): arrows + J/K, ignored inside inputs/contenteditable and when a modifier is held.
- **Rail scrub** (`initRailScrub()`): drag the chapter rail to scrub the page. Needs **both** a `dragstart` preventDefault and `-webkit-user-drag: none` — pressing a link and moving starts the browser's native link drag, which fires `pointercancel`, swallows every later `pointermove`, and releases as a plain click. Moves are tracked on `window` (the rail is a ~26px sliver) and measured from the press origin (`movementX/Y` are not reliably populated).
- **Orb memory**: `restQuaternion` keeps ~34% of wherever you last left the shape, **capped at `MAX_REST_DRIFT`** — each release compounds, and uncapped the logo would eventually face away at the finale.
- **Text melt** (`initTextMelt()`, `[data-melt]` on the section `h2`s): characters, not canvas-sampled pixels — a canvas would have to re-implement font shaping and line breaking. Split lazily and **only after `data-scramble-done`**, since a running scramble rewrites `textContent` every frame. Rest positions are cached in *document* coordinates with transforms cleared (`measure()`): reading a already-transformed box and moving it again by that distance makes letters accelerate away instead of landing. Aims at `orbScreen` (module-level, published by `tick()`).

## Current state — shared layout & other pages

The ambient background (`.stage-wash`, `.stage-ambient`, `.stage-blob` ×2, `.stage-grain`) now lives in `layouts/app.blade.php`, not `home.blade.php` — it renders on **every** page. The sphere canvas lives there too, gated behind `@if (request()->routeIs('home'))`, so it only ever mounts on the homepage.

**Why the canvas had to move, not just get an `@if`:** `<main>` has `position: relative; z-index: 10`, which creates its own stacking context. Early on, the canvas sat inside `@section('content')` (i.e. inside `<main>`) while the other four background layers sat in the layout (i.e. direct children of `<body>`, outside `<main>`'s context). That split the five layers across two different stacking contexts — the canvas, promoted to `<main>`'s z-index:10 context, would have painted *above* the grain instead of under it, even though their own CSS all says `z-index: 0`. Fixed by keeping all five as true siblings outside `<main>`. If the sphere ever needs to render somewhere nested again, re-check this — z-index numbers on the elements themselves don't matter if an ancestor has already put them in different stacking contexts.

`projects/index.blade.php` (Work), `projects/show.blade.php` (case study), and `contact.blade.php` now share the homepage's visual language: `.stage-section` padding, the `.stage-card` / `.stage-card--wide` glass-panel treatment (wide variant added for these — the base 34rem is sized for the homepage's alternating-card layout, too narrow for a form or a full case study), `data-scramble` on their `h1`s, `data-magnetic` on their primary CTAs, and the shared `.tag-pill` class for every tag/tech-stack chip site-wide (previously three different ad hoc pill stylings across home/project-card/show). Sidebar nav now shows an active-page highlight (`request()->routeIs('work.*')` etc.) and a hover micro-interaction (slight translate + tint) on every link, not just a color change.

Cross-document **view transitions** are on (`@view-transition { navigation: auto; }` in `app.css`) — a plain cross-fade between any two pages on the site, no JS. No-ops silently in browsers that don't support it yet (Safari, older Firefox); nothing to maintain there.

## Changelog

**2026-10-07 — Work: shattered mirror (fifth design)** — User's screenshot showed the chrome monoliths after a drag-spin: two slabs edge-on, reading as grey bricks. The real flaw was that the gallery was *blank at rest* — nothing to see until hovered. Offered three directions that broke the "rigid object holding a screenshot" mould; user picked the shattered mirror. Built as one non-indexed `BufferGeometry` of triangular shards from a jittered lattice (`MIRROR_COLS × MIRROR_ROWS`, random diagonals), repositioned on the CPU every frame by `layoutShards(assemble, time)` — a hundred-odd triangles is nothing, and it keeps the stock `chromeMaterial()` (now `flatShading: true`) with real reflections and no shader surgery. Each shard carries its own explode direction (z-biased, out of the plane), tumble axis and `easePower`, the burst-shard trick, so reassembly ripples across the mirror rather than snapping. The lit site is a separate plane (`mirrorScreen`) at the assembled pose, same texture/stale/fade logic the slabs used (`mirrorProject`, `mirrorStale`). The swarm's Work sampler (`sampleSlabs`, name kept) now samples the shattered pose. The slab system is fully removed.
Verified: rest, mid-assembly, lit, project-to-project swap, re-shatter, mobile; swarm morphs; full sweep; interactions; all three engines; adaptive quality. Zero errors. Both effects are derived from values the waypoint system already produces each frame (no new state), and both naturally return to zero as the orb settles at a new resting pose, since `crossing` and the remaining-travel-distance shrink to 0 together. Verified by temporarily exposing the sphere group as `window.__debugSphere` (removed before finishing — don't leave debug globals like this in a shipped build) and logging `x/z/scale/rotZ` across a fine scroll sweep to confirm the dip/shrink/bank peak exactly at the crossing and fully settle at rest; also confirmed visually via screenshots at the logged peak-crossing scroll offsets for two different section transitions. Zero console errors across a full-page scroll sweep.

**Fixed footer: orb/rings bleeding through + clipped left column + redundant copy** — User reported the orb "overflowing" into the footer with screenshots, and disliked the result. Root cause was the *exact same class of bug* already documented above for `<main>`: `<footer>` (`components/footer.blade.php`) had no `position`/`z-index`, so per CSS stacking rules it's a non-positioned in-flow box — which paints **below** the `position: fixed; z-index: 0` background layers (canvas, wash, blobs) regardless of DOM order, letting the beacon orb and orbit rings render on top of the dark footer content. Fixed with `relative z-10` on `<footer>`, matching `<main>`'s existing treatment exactly. Also found and fixed, while verifying: (1) the footer's left column (logo, tagline) was clipped behind the fixed sidebar because `<footer>` was missing the `lg:pl-64` offset `<main>` has — only visible once the orb-overflow bug stopped hiding it; (2) the footer's heading repeated the Contact section's own "Have a project in mind?" copy verbatim — harmless while obscured by the orb, but read as a content bug once actually visible, so changed to "Ready when you are." While in there, brought the footer up to the rest of the site's interaction language it had never gotten: `data-scramble` on the heading, `data-magnetic` on the email CTA, and `hover:translate-x-1`/`-translate-y-0.5` micro-interactions on the link lists (matching the sidebar-nav pattern). Verified via Playwright: no overflow at the Contact→footer boundary, no clipped text, scramble/magnetic both fire correctly, zero console errors. **Lesson reinforced**: any new top-level sibling of the fixed background layers (anything added directly under `<body>`, alongside `<main>`) needs `relative z-10` from the start, or it silently inherits this exact bug — worth checking for next time one gets added.

**Cursor-reactive hero orb** — The hero sphere only ever responded to scroll; on the hero itself (nothing to scroll yet) it just sat there. Added a `mousemove` listener (skipped on coarse/touch pointers) feeding a damped `pointerCurrent {x, y}`, applied in `tick()` as a small additive drift on `sphere.position` plus a slight tilt on `sphere.rotation.x/y` — both scaled by `heroPresence`, which is `1` at the top of the page and eases to `0` within one viewport-height of scrolling. That fade is what keeps this from ever fighting the scroll-driven waypoint pose every other section uses: by the time a section's own `data-sphere-*` pose takes over, the pointer contribution is already zero. Verified via Playwright (mouse moved to opposite screen corners, orb visibly drifts/tilts toward each; after scrolling past the hero, further mouse movement has no visible effect), zero console errors.

**Interactive gem: hovering a skill tag highlights and turns the gem to face that facet** — Skills' tag pills (`<li data-skill-index>` in `home.blade.php`) now drive the gem directly, so it reads as mapped to the list beside it instead of being purely decorative. In `app.js`: the gem's 20 icosahedron faces are bucketed round-robin across however many skill tags exist in the DOM (`gemFaceGroup`), a per-vertex `color` attribute (`gemMaterial.vertexColors = true`) dims non-active facets and brightens the hovered group's (`paintGemColors()`, re-run only when the eased `groupIntensity` actually changes), and — the part that made this actually work rather than just flicker — the gem **turns** to present the hovered group toward the camera (`gemMesh.quaternion.slerp(...)` toward each group's precomputed average local normal aligned to an approximate camera direction). That turn turned out to be load-bearing: the gem auto-spins continuously and independently of scroll, so without it a highlighted facet was just as likely to be rotated round to the back as toward the viewer — caught this via Playwright screenshots during verification, not guessed upfront. On mouse-leave/blur it resumes the normal idle auto-spin from wherever it ended up (no snap back). Tag pills got `tabindex="0"` plus `focus`/`blur` listeners alongside `mouseenter`/`mouseleave`, so keyboard users get the same effect. First color-contrast pass (0.72-1.27 brightness range) was too subtle under the clearcoat's own sheen to read as a clear highlight — widened to 0.52-1.47 after a visual check. Verified via Playwright across all 6 skill tags: gem turns to a distinct orientation per tag, highlighted facet clearly pops, resets cleanly on mouse-leave, zero console errors.

**Fixed broken gem/discs transition (floating-shard artifact)** — The gem (Skills) and discs (Work) were visibly breaking apart into scattered floating triangle shards mid-fade, reported by the user with screenshots and reproduced exactly via a fine-grained Playwright scroll scrub (0.15 viewport-height steps through each handoff). Root cause: `gemMaterial`/`discMaterial` are `transparent: true` with the Three.js default `depthWrite: true` — on a flat-shaded, non-indexed mesh (or a stack of several overlapping discs), there's no guaranteed back-to-front triangle draw order, so whichever facet rasterises first writes depth and blocks/overwrites others unpredictably once opacity is partial. At full opacity (steady state, e.g. the final Skills/Work screenshots) this was invisible; it only showed up *during* the cross-fade, which is why earlier verification (full-section screenshots only) missed it. Fix: added `depthWrite: false` to both materials — the standard fix for fading/overlapping translucent geometry. Also changed the reveal from a flat opacity fade to a scale-pop (`0.55 + progress * 0.45` on `gemMesh`/`discGroup`), so the shape visibly materialises rather than just fading in, which was also the "make it more unique" half of the user's feedback — the transition itself is now a deliberate moment instead of looking like a glitch. Verified clean via the same fine-grained scroll scrub post-fix: no shards at any intermediate step, zero console errors.
